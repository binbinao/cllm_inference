## P0 级问题（必须用户确认）

### P0-1: HTTP 服务器实现方式

- **问题**：HTTP 推理服务层是纯 C++ 标准库自研（自写 socket + 线程池 + HTTP/1.1 解析 + SSE），还是引入轻量第三方库（如 cpp-httplib 单头文件）？这决定"从 0 开始"是否延伸到网络层，影响依赖策略与代码量。
- **位置**：新增 `src/server/` 模块
- **方案**：A. 纯标准库自研 HTTP 服务器 / B. 引入 cpp-httplib 单头文件库 / C. 其他
- **推荐**：A（纯标准库自研），符合"从 0 自研、不引入第三方框架"的整体定位，HTTP/1.1 + SSE 需求本身不难，可控性强
- **决策**：A → 纯 C++ 标准库自研 HTTP 服务器（socket + 请求线程池 + HTTP/1.1 解析 + SSE 流式响应）

### P0-2: int4/int8 量化内核的 SIMD 向量化范围

- **问题**：量化矩阵乘内核是否要求 SIMD 向量化（x86 AVX2 / ARM NEON）？这影响性能目标、实现复杂度与可移植性，也决定是否引入编译器内置函数。
- **位置**：新增 `src/core/quant/` 模块
- **方案**：A. 先纯标量 C++ 实现跑通正确性，SIMD 作为后续优化 / B. 首版即要求 AVX2 + NEON 向量化 / C. 仅支持当前平台（macOS ARM NEON）
- **推荐**：A（先标量跑通正确性，预留 SIMD 抽象接口，后续增量优化），降低首版风险，且"内核加速"可通过多线程 + 紧凑数据布局先获得一部分收益
- **决策**：A → 先纯标量 C++ 实现跑通正确性，预留 SIMD 抽象接口，SIMD 向量化作为后续增量优化

### P0-3: 量化内核精度目标

- **问题**：int4/int8 量化内核的输出精度要求是"与 float 参考实现 bit-exact 一致"还是"允许采样级数值误差（结果语义正确即可）"？这决定反量化/点积的实现策略与测试基准。
- **位置**：新增 `src/core/quant/` 模块
- **方案**：A. 允许采样级误差（对齐 llama.cpp 的量化精度语义） / B. 严格要求 bit-exact / C. 其他
- **推荐**：A（量化本身就有损，业界一致以"生成文本合理"为验收标准，bit-exact 对 Q4_K 等块量化不现实）
- **决策**：A → 允许采样级数值误差，以"生成文本语义合理"为验收标准

### P0-4: 构建与测试依赖

- **问题**：是否允许引入测试框架（如 GoogleTest / Catch2）用于单元测试，还是手写 assert 测试？这影响 CMake 依赖与测试策略。
- **位置**：`CMakeLists.txt`、新增 `tests/` 目录
- **方案**：A. 引入轻量测试框架（Catch2 / GoogleTest via FetchContent） / B. 手写 assert 测试，零第三方依赖 / C. 其他
- **推荐**：B（手写断言测试，保持零第三方依赖的定位；核心数值模块可用独立 test 程序覆盖）
- **决策**：A（用户选择）→ 引入 Catch2 测试框架（FetchContent），仅测试依赖，运行时保持零第三方依赖
